# NovelDNA

> ⚠️ **本项目定位：本地语料向量检索 + 文本行文风格特征分析工具。
> 面向个人写作爱好者，用于**世界观设定检索、文本句式与叙事风格分析。

## ✨ 项目简介

本项目基于 Streamlit + ChromaDB + Ollama 搭建**本地优先 RAG 架构**。

1. 文本分片、Embedding 向量化全部在本地使用 Ollama 的`bge-m3`完成，**原始文本不会上传至任何云端 API**。
2. 用户提问时，本地 Chroma 向量库完成相似度检索，**仅少量高度相关片段 + 用户问题**会提交给大模型（支持云端 API / Ollama 本地模型两种推理方式）。
   - ✅ 大幅降低云端 Token 开销
   - ✅ 保护私人小说 / 语料隐私，完整原文不会外发
3. 支持两种风格解析模式：
   - **单本风格分析**：仅提取单部作品的行文特征，不同作品之间世界观隔离，避免设定串扰
   - **作者风格分析**：读取所上传的作者全部语料，提取跨作品的整体叙事、用词习惯
4. 支持两份风格档案进行对比分析。

> 📌 关于风格分析模板：
> 项目中 `skill/writing-dna-skill` 目录下的风格分析模板，**搬运自开源项目 writing_DNA**。模板仅负责定义风格分析的提示词框架，**本项目主体代码、RAG 检索逻辑、界面、作品隔离功能均为独立开发**。

## 🧩 核心架构

```
原始文本 → 本地切片 → Ollama(bge-m3)本地Embedding → 本地Chroma向量库
用户提问 → 本地生成查询向量 → 本地相似度检索 → 筛选少量相关片段
→ 将【风格档案 + 检索片段 + 用户提问】送入LLM（云端API / Ollama本地模型）
→ 返回世界观查询结果 / 文本风格分析结论
```

- Embedding 模型：`bge-m3`，Ollama 本地计算，文本不送往第三方嵌入服务
- 向量数据库：ChromaDB，持久化存储在本地`db`文件夹
- LLM 推理二选一：
  - 云端 API：智谱 GLM、硅基流动、通义千问、DeepSeek
  - Ollama 本地模型：完全离线运行，所有推理本地完成

## 📋 前置准备

1. 安装 Python >=3.10
2. 安装 Ollama，拉取嵌入模型（终端执行）

```
ollama pull bge-m3
```

> 可选：本地大模型，例如 `ollama pull qwen2.5:7b`

3. 保持 Ollama 后台运行（`ollama serve`）

## 🚀 快速启动（Windows）

1. 克隆项目到本地

```
git clone https://github.com/xavierxeno/NovelDNA.git
cd NovelDNA
```

2. **首次使用：双击 `do_first.bat`**，自动安装全部 python 依赖
3. 依赖安装完成后，双击 `启动.bat`，自动打开浏览器访问 `http://localhost:8501`

> Linux/Mac 用户：手动执行 `pip install -r requirements.txt`，再执行 `streamlit run app.py`

## 📖 使用指南

### 1. 上传并入库语料

1. 侧边栏新建作者，填写作者名称
2. 填写**作品名**（必填，用于多作品隔离，检索 / 分析时限定单本书）
3. 上传文件，支持格式：`.txt` / `.md` / `.docx` / `.doc`
4. 点击【保存并入库】，程序自动切片、本地向量化存入向量库

### 2. 风格档案分析（核心功能）

侧边栏「分析」模块，二选一模式：

- ✅ **单本风格（推荐）**：选定已入库单部作品，生成该作品专属风格档案，保存在`setting/作者名/`
- **作者全局风格**：读取该作者全部语料，生成跨作品整体风格档案

> 风格档案仅提取句式、叙事视角、词汇偏好、对话习惯等语言层面特征

### 3. 语料检索查询

1. 侧边栏「限定作品」下拉框，选定目标作品（推荐！自动隔离其他作品设定防止设定互串）
2. 在底部输入框提问，示例：
   - 查询世界观人物背景设定
   - 分析文本叙事节奏、句式特征
3. 系统本地检索，仅召回少量相关片段送入大模型回答

### 4. 风格档案对比

选择两份已生成的风格档案，调用模型对比两者行文风格差异。

## 📌 注意事项

1. `.doc` 旧版 Word 文档读取依赖 Windows 系统 + 安装 Microsoft Word；Mac/Linux 建议转为 docx/txt。
2. Ollama 必须保持后台运行，否则本地 Embedding、本地 LLM 会报错。
3. 侧边栏「检索片段数」可调整，数值越大召回文本越多，token 消耗越高。
4. 切换限定作品时，对话上下文自动隔离，不同作品使用独立会话。
